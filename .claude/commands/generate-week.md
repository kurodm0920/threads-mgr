# /generate-week

`/today-rest` と `/tomorrow-morning` を統合した週次一括生成コマンド。1コマンドで **7日 × 5スロット = 35投稿** を生成・予約する。

起動推奨タイミング: **日曜の夜（22:00〜）**。次の月曜0:00 JST 以降に始まる7日分を生成。

## 実行手順

### 1. 環境変数読み込み

```bash
source <(grep -v '^#' .env.local | sed 's/^/export /')
```

### 2. 過去2週間のデータ取得

```bash
curl -k -s -H "Authorization: Bearer $CC_API_KEY" \
  "https://localhost:3001/api/cc/inspirations-export?days=14" \
  > /tmp/cc-export-week.json
```

ローカル dev が動いてない場合は本番URLで取得:

```bash
curl -s -H "Authorization: Bearer $CC_API_KEY" \
  "https://threads-mgr.vercel.app/api/cc/inspirations-export?days=14" \
  > /tmp/cc-export-week.json
```

または Supabase REST API で直接取得（dev が起動してない時のフォールバック）。

このJSONには:
- `published_posts`: 過去投稿
- `post_metrics`: 各投稿の数値（views/likes/replies/reposts/quotes）
- `post_features`: 抽出済み特徴
- `inspirations`: 業界バズ投稿（手動 + keyword_trend）
- `recent_knowledge`: 最新ナレッジサマリー

### 3. 分析

`/tmp/cc-export-week.json` を読み込み、以下を抽出:
- **winners**: 24h views が上位30% の投稿（直近2週間）
- **losers**: 24h views が下位25% の投稿
- **inspirations の傾向**: 文字数中央値、絵文字数、冒頭パターン、頻出キーワード
- **時節**: 来週の占星術イベント（新月/満月/惑星逆行/星座シーズン切替）を確認

### 4. 週間スロット計算

起動日（通常は日曜夜）の翌日0:00 JST から始まる7日 × 5スロット = 35スロットの `scheduled_at` を計算。

スロット時刻（JST → UTC 変換）:
| スロット | JST | UTC |
|---|---|---|
| 朝 | 07:30 | 前日 22:30 |
| 昼 | 12:15 | 当日 03:15 |
| 夕 | 18:00 | 当日 09:00 |
| 夜 | 21:30 | 当日 12:30 |
| 深夜 | 23:45 | 当日 14:45 |

### 5. 35投稿の配分

**ジャンル配分**（7日合計）:
- 西洋占星術 50% → 17〜18投稿
- 四柱推命 20% → 7投稿
- 紫微斗数 15% → 5投稿
- 易経 15% → 5投稿

**コンテンツタイプ配分**:
- 共感系 40% → 14投稿
- 豆知識系 25% → 9投稿
- 今日の運勢 20% → 7投稿
- ストーリー型 10% → 3〜4投稿
- CTA投稿 5% → 2投稿（週2回、火曜深夜・金曜深夜 推奨）

**スロット別の指針**:
- 朝7:30: 運勢 or 共感（フォロワー外にも届きやすい）
- 昼12:15: 豆知識 or 共感
- 夕18:00: ストーリー or 豆知識
- 夜21:30: 共感 or 運勢
- 深夜23:45: CTA（週2回）or 共感 or ストーリー

**バリエーション保証**（必須）:
- 同じ書き出しパターンが3日連続にならないように
- 同じジャンル × 同じスロットが連続しないように
- CTA投稿は曜日を分散

### 6. 生成（35投稿）

文体・文字数・禁止語は CLAUDE.md 準拠:
- 文体: 平常時は「〜だよ」基調、CTAだけ丁寧語、占い系の落ち着いた語り
- 文字数: 200〜450字
- 禁止語: 「絶対」「100%」「必ず」「確実」など断定表現

過去 winners のトーン・構成を踏襲、losers のパターンを回避、inspirations の業界傾向を反映。

### 7. プレビュー（3段階表示）

**Step 1: 全体サマリー** を最初にユーザーへ提示:

```
週間サマリー（5/20 月〜 5/26 日）
─────────────────────────────────
ジャンル配分: 西洋18 / 四柱7 / 紫微5 / 易経5
タイプ配分:   共感14 / 豆知識9 / 運勢7 / ストーリー4 / CTA2

CTA曜日: 火曜深夜 / 金曜深夜

各日のテーマ:
  月 5/20: 牡牛座シーズン終盤 / 月始まり共感
  火 5/21: 双子座入り / コミュニケーション運
  ...
```

**Step 2: 日ごとの全文プレビュー**（順次提示、長いので必要な日だけ展開する形でもOK）:

```
=== 月 5/20 ===
[7:30  astrology/fortune] "..."（300字）
[12:15 shichu/tips      ] "..."（280字）
[18:00 shibun/story     ] "..."（350字）
[21:30 astrology/empathy] "..."（260字）
[23:45 iching/empathy   ] "..."（240字）
```

**Step 3: ユーザー操作**

- 全体OK → 「OK」「生成して」「予約して」→ Step 8 で一括 INSERT
- 個別修正 → 「月の昼の投稿、絵文字外して」「火曜のCTA、もっと柔らかく」→ ピンポイント差し替え
- 全体やり直し → 「もう少し恋愛運寄りで再生成」→ 全体再生成

### 8. POST /api/cc/posts-bulk（35件一括）

```bash
curl -k -X POST \
  -H "Authorization: Bearer $CC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"posts": [/* 35件の配列 */]}' \
  https://localhost:3001/api/cc/posts-bulk
```

API 側は `max(50)` まで対応済み（`src/app/api/cc/posts-bulk/route.ts:18`）なので35件は余裕。

### 9. 結果報告

投入された投稿のID・時刻リストをユーザーに報告し、以下を案内:

```
✅ 35投稿の予約完了。
   - 最初の投稿: 5/20(月) 7:30 JST
   - 最後の投稿: 5/26(日) 23:45 JST

ダッシュボードの /calendar で予定一覧が見られます。
個別修正は /drafts ページから可能です。
```

## 出力長制約への対策

35投稿 × 300字 = 約10,500字 + 構造化メタデータ で、Claude の出力トークン上限に近づく可能性。1ターンで完走できなさそうな場合:

- 前半（月〜木の20投稿）と後半（金〜日の15投稿）の2回に分けて生成
- 最終 POST は2回分を統合して1回の bulk INSERT で投入（生成バッチID `generation_batch_id` を共有）

## 注意

- 突発トレンド（占星術の急な話題、ニュース等）には追従できない → `/drafts` で個別差し替え可能
- 過去 winners を踏襲しつつ、書き出しパターンが連続3日同じにならないように分散
- inspirations の業界傾向（特に keyword_trend で集めたバズ投稿の構造）を反映
- 占術倫理（断定表現NG）を厳守
